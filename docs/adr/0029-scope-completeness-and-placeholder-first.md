# 0029 范围口径：规格内无永久出界，占位优先，完整性先于真实渠道取证

**Status**: accepted

《渔力全开》规格拆出的验收矩阵有 523 条条款，但一直没有统一的完成口径：5 条被写成永久出界，17 条被外部交付理由挂成阻塞，试玩又暂时不可用，于是「哪些玩法真的写完了」没有唯一答案。维护者也没有机器判据来判断一条条款有没有代码落点。本 ADR 定的是**范围与取证口径**：谁在范围内、范围外的说法如何消失、外部参数缺位时凭什么算写完、以及这些判断由哪份台账与哪道门禁守住。

它接管 [ADR-0028](0028-solo-clear-on-shared-world.md) 中关于「延期」与「以占位资源结项」的表述（见第六节），其余决定继续有效。

## 决定

### 一、唯一范围 = 规格内的全部条款

- 范围由 [验收矩阵](../acceptance/README.md) 的条款给出，不靠记忆或单据划定。**规格内没有永久出界**：`out-of-scope` 仍是词表里的合法值，但《渔力全开》的条款一律不用它。
- 原先划出的 5 条（9-19～9-23：小队系统、队伍界面、邀请交互、队伍入档、队伍界面可读性）全部收回：前 4 条改 `unverified` 并按依赖排期，第 9-23 条是只能试玩观察的可读性条款，改 `blocked` 并写试玩口径。
- **唯一允许的暂不可执行**是 56 条只能在地图里观察的 C 级条款（贴地、净空、遮挡、可读性、手感、整体旅程，含随小队系统排期的界面可读性 9-23）：状态 `blocked`，理由写「卡在：需编辑器试玩取证」，试玩恢复后整批取证。它是排期事实，不是范围裁剪。
- 状态只在**真取证之后**流转：`unverified` 不预先写证据，`evidenced` 必须配一个真实存在的仓库相对路径。「已取证只增、遗留测试只减」的单向棘轮继续生效（[ADR-0027](0027-clause-matrix-as-sole-acceptance-surface.md)）。

### 二、术语：「玩法实现」与「业务范围」不是一回事

两个词都用中文，含义不同，**不得互相替代**（正表见 [GLOSSARY](../../GLOSSARY.md)）：

| 词 | 指什么 | 机器真源 | 明确不指 |
| --- | --- | --- | --- |
| **玩法实现（Gameplay implementation）** | 能让一条验收条款成立的三端业务代码：`client/`、`common/`、`server/` 下的业务模块与共享配置 | 代码本身；条目的真源是实现覆盖表 | 各端 `packages/` 包目录、`tools/` 工具目录 |
| **业务范围（Business scope）** | 质量工具与架构图度量的源码集合，不含任何 `packages/` 子树 | 根目录 `uml-quality.json` 与 `policy.edn`（[ADR-0021](0021-packages-outside-business-scope.md)） | 玩法实现的完成度，也不是交付范围 |

判据：问「这条玩家规则由哪段代码负责」时用玩法实现；问「质量工具量哪些文件」时用业务范围。

### 三、占位优先，完整性先于真实渠道取证

外部依赖不再作为阻塞理由，只作为**生产开关**（第四节）。缺参数时按下面五条走通完整路径：

1. **占位参数集中在共享配置**：平台商品 ID、广告位、成就 ID、汇率、正式资产 ID 一律进 `common/GameCfg.lua` 与 `common/cfg/` 的内容表，不散落在业务分支里。真实参数到位后只替换配置，不改玩法判定。
2. **平台能力只经可替换适配层**：业务不直接调用平台服务，全部经 `server/platform_host.lua` 这一类适配层；成功与失败两条路径都要能走通。
3. **本地连接夹具证明代码路径**：容量、加入与离开、共享世界状态用本地连接夹具证明，夹具只证明代码路径完整，**不宣称真实容量或真实多人行为已验收**。
4. **占位不发放真实付费权益**：占位支付、占位广告、占位商品一律不产生真实付费权益；真实平台结论只在真实平台上取，且单列为生产开关。
5. **占位通道默认不许进发布构建**：占位支付 / 广告 / 分享共用一道闸门——默认只在调试构建（`GameCfg.Debug.Enabled`）可用，发布构建必须显式把 `GameCfg.Platform.Placeholder.AllowInPublish` 置 `true`。闸门关闭时占位动作一律拒绝、不发任何物品与权益，回执写「未开放」（`reason = 'not_open'`）。这条不是口头约定：机器判据是 `tests/native/spec/17_platform_boundary_placeholder_test.lua` 与 `tests/native/spec/11_ad_revive_placeholder_test.lua` 的发布构建闸门用例（条款 19-13）。

### 四、生产开关台账

下面每一项都是**真实渠道事项**，不是阻塞理由：缺位时用占位参数或本地夹具走通流程，到位后只替换配置或补一次真实取证。台账的权威版本就是本节，条款与文档只引用，不另抄一份。

| 序号 | 生产开关 | 缺位时的占位方式 | 真实交付后 | 明确不宣称 |
| --- | --- | --- | --- | --- |
| 1 | 平台商品 ID（金豆与乐园币商品） | `GameCfg.Platform.Goods` 的占位行；购买走占位 flow | 替换 goodsId 字段，判定不动 | 占位不发放真实付费权益 |
| 2 | 广告位 | `GameCfg.Platform.Ads` 的占位标识；广告适配层的成功与失败两路可走 | 替换广告位参数 | 占位不发放真实付费权益 |
| 3 | 平台成就 ID | 占位成就 ID；本地完成标记可重复补交 | 替换成就 ID 并补交 | 占位不宣称平台已授予 |
| 4 | 金币兑换汇率 | 占位汇率走通购买与到账 | 替换汇率 | 占位汇率不代表真实定价 |
| 5 | 正式资产 ID | `common/cfg/PlaceholderAssets.lua` 的占位资源 | 按官方资产表替换显示 | 占位只改显示，不改判定参数 |
| 6 | 全服纪录 | 界面按「未取得数据」展示，不显示虚构纪录 | 接入纪录服务 | 占位不显示虚构纪录 |
| 7 | 容量（真实平台实测） | 本地连接夹具 8 名以上虚拟连接 | 真实平台容量实测 | 夹具不宣称真实容量 |
| 8 | 发布检查 | 检查项汇总为本台账与矩阵门禁 | 发布前逐项签署；其中「占位通道不进发布构建」一项不靠人签，改由可执行检查代替：`lua tools/cli.lua test spec -- --filter='19%-13'` 必须全绿（关闭调试且 `AllowInPublish=false` 时占位支付、金币页、广告与分享一律被拒、不发权益、回执写「未开放」） | 门禁全绿不等于可发布；签署项与机器项分开记账 |
| 9 | 真实支付与广告通道 | 占位通道的扣费与发奖对称结算；占位通道默认只在调试构建可用，发布构建须显式 `GameCfg.Platform.Placeholder.AllowInPublish = true` | 真实通道验收，同时把占位通道关掉 | 占位不发放真实付费权益；占位通道默认关闭由 19-13 的断言守着 |
| 10 | 真实多人环境 | 本地连接夹具证明加入、离开与共享世界状态 | 真实多人验收 | 夹具不替代真实多人结论 |
| 11 | 正式美术资源交付 | 占位资源下玩法表现仍可观察 | 按清单交付后复验 | 占位通过不算资源结项 |
| 12 | 盲盒是否平台功能（抽奖 / 随机能否走平台商品） | 自研随机 + 占位商品走通抽奖与结算，概率与货币取自 `GameCfg` | 若平台开放盲盒 / 抽奖能力，改走平台接口并把随机交给平台 | 自研随机不宣称与平台盲盒的概率或合规口径一致 |

### 五、静态门禁

- 实现覆盖表已按 [ADR-0039](0039-acceptance-surface-as-feature-files.md) 删除：条款只剩 ID 与文案两格，证据等级写成文案的行尾后缀，代码落点改由 `tests/native/spec/` 的条款断言表达。
- 静态校验并入 `tools/acceptance.lua`，随 `lua tools/cli.lua acceptance --check` 与 fast 车道运行：ID 连续、禁用措辞、索引一致、证据文件不引用孤儿条款号、已取证只增。
- 状态从证据文件反推，不再手写；逐条结果可用 `lua tools/cli.lua acceptance --infer` 查看。

### 六、与旧 ADR 的接管关系

- 本 ADR **接管** [ADR-0028](0028-solo-clear-on-shared-world.md) 中关于「真实双账号、真实设备与容量验收继续延期」与「占位资源期间」的表述：延期不再是条款级阻塞，真实渠道事项一律改记为本 ADR 的生产开关；「不以占位资源通过作为结项」改口径为「占位走通代码路径 + 生产开关单列」，占位仍不发放真实付费权益、仍不算真实渠道结项。
- **继续有效、本 ADR 不改动**：Solo clear 是唯一玩法目标；只有一套服务端权威实现，不为单人另写管理器；四类证据（正常流程、失败流程、退出重进、存档恢复）缺一不可；外部依赖各归各的出口；个人状态与共享世界状态的边界。
- [ADR-0027](0027-clause-matrix-as-sole-acceptance-surface.md) 的「验收矩阵是唯一验收面」继续有效；本 ADR 只改范围口径，不动矩阵的条款格式与门禁种类（格式已于 [ADR-0039](0039-acceptance-surface-as-feature-files.md) 调整为两列）。

## 理由

**出界会把「没做」永久化。** 一条条款被划出范围后就不再有人排期，它既不在待办里也不在缺口里，最终没人能回答它到底该不该做。规格内没有永久出界，才能把「哪里没做完」收敛成一个数。

**占位与真实渠道是两件事，不能互相冒充。** 用占位参数走通购买流程，证明的是代码路径完整；用真实商品 ID 走通，证明的是渠道可用。把前者当成后者，会把模拟成功写进验收结论；把后者当成前者的前置，会让玩法被美术与商业化排期拖住。分开记账，两边都不会说谎。

**机器判据优先于人记性。** 「每条非试玩条款都有代码落点」只有变成门禁才是真的；否则覆盖率迟早退化成一份过期的表。

## 后果

- 矩阵的 `out-of-scope` 计数归零，`blocked` 只剩 56 条试玩条款；新出现的出界状态由评审直接拒绝，不靠门禁。
- 生产开关台账成为发布前的唯一清单；它不在矩阵里，也不进条款状态，避免把渠道进度与玩法完成度混成一个数。
- 覆盖表按小节逐节扩大，每扩大一节就要补齐该节的代码落点；空落点会让 fast 车道变红。
- 真实渠道结论永远晚于玩法完成，这是刻意的：玩法不再等待渠道，渠道也不被玩法宣称已完成。
