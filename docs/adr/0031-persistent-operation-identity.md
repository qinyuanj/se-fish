# 0031 持久会话 fencing 与操作身份分层

**Status**: accepted

存档读取、会话认领、写入和外部实体交付都是异步的。重连、重复点击、迟到回包和写后重试会让同一业务动作到达多次；如果客户端自报身份、每次重试换新身份，或先改正式状态再尝试落账，就无法区分新操作与重放。DataStore 写入与引擎单位生成也不是一个原子事务，不能用“执行过一次”代替可恢复协议。

## 决定

### 一、会话先 fencing，再接受写操作

`MgrSave` 为每次加载颁发独立 `Token`，认领时推进 `epoch` 并写入 `meta.session`。后续写入同时校验当前会话、`Token`、`epoch` 和 `revision`；异步回调继续执行前再次确认会话仍有效。旧会话即使迟到，也不能覆盖新会话。

### 二、三类身份分别解决三个问题

| 身份 | 生成与作用域 | 职责 | 不能承担 |
| --- | --- | --- | --- |
| 客户端 `seq` | 客户端按通道或界面递增；服务端用会话 `Token + kind + seq` 形成 `requestKey` | 拒绝同一会话内的旧请求、关联请求与回包 | 不是持久操作凭证，不能跨会话自行复用 |
| 持久 `operation` | `MgrSave:NextOperation` 生成 `{ id, sequence, kind, requestKey? }` | 隔离 draft、同键落账、记录结果并重放 | 不由客户端自造，不在重试时重新颁发 |
| 多阶段 `requestId` / 交付键 | 服务端为支付意图或待交付物生成稳定键 | 跨回包、重连和多次写入查询原意图，幂等完成外部交付 | 不等同于 `MgrSave` 的 `operation.id` |

回包里的 `operation.id` 只作为该通道的结果去重键；盲盒等流程可以同时拥有持久操作身份和独立交付意图身份，调用方不得把两种标识混成一份协议。

### 三、同键落账，外部副作用按稳定身份确认

- `MgrSave:Execute` 只在隔离 draft 上运行 `transform`。扣费、物品变化、恢复记录、操作身份与结果进入同一个快照，写确认后才替换正式数据。
- 已记录的操作按原身份返回原结果；身份相同但 `kind` 或 `requestKey` 不同属于冲突。操作记录有界，超出保留期必须明确返回 `expired`，不能当成新操作重发权益。
- 引擎单位生成等外部副作用不能并入 DataStore 原子写入。需要交付时，先持久化待交付记录，再用稳定交付键执行幂等交付，最后落账清除记录；中途失败保留恢复入口。
- 客户端用结果身份抑制重复动画或重复展示，只是表现去重，不替代服务端重放与交付恢复。

## 备选方案（拒绝）

1. **信任客户端自报操作 ID**：无法防止伪造、碰撞和跨会话重放。
2. **每次重试生成新身份**：服务端会把重试当成新交易，重复扣费或发奖。
3. **直接修改正式数据后再序列化**：写失败时内存与持久状态分裂，恢复无明确边界。
4. **假定 DataStore 与引擎副作用同时成功**：进程或会话在两者之间中断时无法恢复。

## 后果

- 重试必须保留原 `operation` 或 `requestId`；断线恢复先查询原意图，不用新 `seq` 再发一次相同权益操作。
- 本 ADR 只约束已接入 `MgrSave` 的持久路径；未接入通道不得宣称具备持久幂等和跨会话恢复能力。
- 现存多阶段流程仍含手工补偿与无存档直结分支，后续应分别迁移到上述协议；本 ADR 不把这些分支视为已经完成的统一实现。
