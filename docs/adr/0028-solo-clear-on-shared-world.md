# 0028 Solo clear 跑在真实多人骨架上，不另立单机实现

**Status**: accepted

玩法规格描述的是一套**服务端权威的多人共享世界**，而本轮要交付的验收场景只有**一个真实账号**。两者之间有两种听起来都合理的捷径，两种都会把本期变成未来必须拆除的分支：

- 为单人另写一套管理器、独立任务逻辑或特殊结算路径——验收过的代码在真实多人里跑不到；
- 用 NPC 模拟玩家、虚拟连接、人口补位或「教程协作者」把在线人数凑够——验收结论描述的是一种不存在的玩家。

本 ADR 记录为什么两条都不选、以及改用什么口径。它约束的是后续所有业务系统的交付方式，不是一次性排期。

## 决定

### 玩法目标：Solo clear

**独立完成（Solo clear）**是本轮唯一的玩法目标：一名真实玩家，在没有任何其他真人、没有模拟者、没有付费、也不依赖稀有抽奖大奖的条件下，能走完新手教程、七区成长、各首领与最终交付。它不是「多人玩法的一个降级开关」，而是对**现有玩法本身**的可行性要求：不付费、不靠指定抽奖结果，正常路线必须存在。

### 实现：只有一套服务端权威实现

- 单账号描述的是**当前在线只有一个真实玩家**这一事实，不是一种运行模式。它不触发另一套单人管理器、独立任务逻辑或特殊结算路径。
- 客户端只发送操作意图与展示状态；库存、伤害、任务、经济与世界结果一律由服务端决定。
- 玩家身份的真源仍是引擎提供的真实玩家对象；不信任客户端提交的用户身份。
- 生命周期继续走现有入口统一管理加入、存档就绪、退出、重进与异步回调顺序，不另建平行入口。

### 状态边界：个人归个人，世界归世界

| 归属 | 内容 |
| --- | --- |
| 个人持久状态（按真实用户身份保存） | 金币、库存与实例倍率／烤制状态、装备与弹匣、升级／购买／药水次数、成长、任务、剧情已读、图鉴个人纪录、区域到达集合、盲盒保底、成就、濒死／死亡与恢复状态 |
| 个人会话状态（退出只清本人） | 抛竿、收线、施法、烧烤、设施占用、界面会话 |
| 共享世界状态（世界级真源，不进个人存档） | 活鱼、地面物品与刷新点、航线、公共设施 |

共享对象可以带归属元数据（所有者、持有者、操作者），但归属只用于权限与结算，**不改变对象的世界唯一性**，也不把它复制进个人存档。

### 改动策略：按缺口动手，不做无证据重写

优先复用现有的生命周期、钓鱼、战利品、教程与设施接缝。只有当业务缺口、测试失败或实机证据指向某处时才做局部修改；不预设全仓玩家解耦，也不为测试而在业务模块里加调试跳关入口。新增或调整管理器、界面处理、共享配置与依赖关系时，遵守仓库既有的分层、入口注册与配置集中约定。

### 完成口径：四类证据缺一不可

每个业务系统同时交付四份证据：**正常流程**、**失败流程**、**退出重进**、**存档恢复**。低概率专项（稀有鱼种、大奖、特殊效果、首领阶段）可以用可重跑探针补覆盖，但必须与正常通关证据**分栏记录**，探针不能替代正常路线。

完成门槛是**原生测试 + 单账号编辑器实机**两条。真实双账号、真实双客户端、真实设备与容量验收继续延期，不阻塞本期业务交付，也不因「本期单账号验收通过」而被宣称已完成。

### 外部依赖各归各的出口

- 正式美术资源是**交付依赖**，与玩法条款分开验收；占位资源期间，玩法表现必须仍然可观察、可验证。
- 真实商品、广告、支付、平台成就与全服纪录不伪造外部参数或生产权益；编辑器内只接一层可替换适配层并跑通失败路径，真实平台结论只在真实平台上取。
- 存档兼容默认保留现有财产，新增字段用显式默认值与版本迁移；任何清档或破坏性迁移都需单独确认。
- 平台回调缺少唯一凭证时，不得声称跨会话幂等已成立。

### 执行分工

业务按闭环与依赖拆分执行：**可玩版本收尾**汇总正常路线与整体验收，**战斗与交互试玩**承接实机观察，**资产占位**负责引擎内置资源临时顶位，**正式资源**、**真实平台**与**发布决策**各自独立跟踪；远期多人事项单独保管，恢复排期时才重开。同一整体验收不重复拆给多个执行方向。

## 理由

**单机分支的代价是终局性的。** 一旦业务逻辑出现第二套入口，后续每一次改动都要在两条路径上验证；而真实多人路径恰恰因为「本期不做」而没人验证，等于把不确定性推迟到最不该出问题的时候。

**模拟参与者会污染验收结论。** 用 NPC 或虚拟连接凑在线人数，产出的证据无法区分「一名玩家能完成」与「一名玩家加上若干机器人能完成」。后者不是本期的目标，前者才是需要被证明的那句话。

**口径分离让「没做完」不被冒充成「做完了」。** 模拟结果、单账号结果、真实平台结果与远期多人结果分栏记录，任何一项缺失都只影响它自己那一条，不会让整张验收结论失效或虚高。

## 后果

- 新增业务系统的评审必须同时回答两问：它在真实多人路径上是否可达？它的失败与恢复路径是否有证据？
- 占位资源是合法的中间态，但「占位可玩」不等于「正式资源已交付」，两条口径在验收矩阵里各自成行。
- 真实多人、真实设备与容量验收长期处于阻塞态，直到排期恢复；这不影响业务完成度，但影响对外发布的判断。
- 单据不再是交付状态的载体：未完成项由验收矩阵的条款与状态承载，外依赖由带具名阻塞理由的条款承载。
