# 0028 Solo clear 跑在真实多人骨架上，不另立单机实现

**Status**: accepted（关于外部依赖与生产开关的口径由 [ADR-0029](0029-scope-completeness-and-placeholder-first.md) 补充）

玩法规格描述的是**服务端权威的多人共享世界**，但日常验收主路径是**单真实账号**。为单人另写独立逻辑或用 NPC 模拟玩家，都会制造未来必须拆除的分支或污染验收结论。

## 决定

### 1. 玩法目标：Solo clear
一名真实玩家在没有其他真人、没有模拟者、不付费、不依赖稀有抽奖大奖的条件下，必须能走完新手教程、七区成长、各首领与最终交付。

### 2. 只有一套服务端权威实现
- 单账号只是「当前在线 1 名真实玩家」的运行态，不是独立模式；不为单人另写管理器、任务逻辑或结算路径。
- 客户端只发操作意图与展示状态；库存、伤害、任务、经济与世界结果一律由服务端判定。
- 玩家身份真源是引擎提供的真实 `Player` 对象，不信任客户端自报身份。

### 3. 状态边界：个人归个人，世界归世界

| 归属 | 内容 |
| --- | --- |
| 个人持久状态（按真实用户身份保存） | 金币、库存与实例倍率/烤制状态、装备与弹匣、升级/购买/药水次数、成长、任务、剧情已读、图鉴个人纪录、区域到达集合、盲盒保底、成就、濒死/死亡与恢复状态 |
| 个人会话状态（退出只清本人） | 抛竿、收线、施法、烧烤、设施占用、界面会话 |
| 共享世界状态（世界级真源，不进个人存档） | 活鱼、地面物品与刷新点、航线、公共设施 |

共享对象可带归属元数据（所有者/持有者/操作者），只用于权限与结算，不改变其世界唯一性，不复制进个人存档。

### 4. 四类证据缺一不可
每个业务系统同时覆盖四栏：**正常流程**、**失败流程**、**退出重进**、**存档恢复**（与 A/B/C 三档取证方式正交）。低概率专项探针与正常路线分栏记录，不互相替代。

### 5. 外部依赖各归各的出口
- 正式美术资源与玩法条款分开验收；占位期间玩法表现须可观察、可验证。
- 商品、广告、支付、平台成就与全服纪录不伪造生产权益，编辑器内只经可替换适配层跑通成功与失败路径；真实渠道结论单列进[生产开关台账](../acceptance/production-switches.md)（[ADR-0029](0029-scope-completeness-and-placeholder-first.md)）。
- 存档兼容默认保留现有财产，新增字段用显式默认值与版本迁移；清档或破坏性迁移须单独确认。
- 平台回调缺唯一凭证时，不得宣称跨会话幂等已成立。

## 拒绝的方案

1. **单机分支**：增加第二套入口，真实多人路径长期无验证，隐患推迟到最难修的阶段。
2. **NPC / 虚拟连接凑人数**：无法区分「一名玩家能通关」与「带机器人通关」，污染验收结论。

## 后果

- 评审新业务系统必须确认：在真实多人路径上可达，且失败与恢复路径有证据。
- 单账号通过不代表真实多人、真实设备或容量验收完成；真实渠道与多人结论独立记账。
