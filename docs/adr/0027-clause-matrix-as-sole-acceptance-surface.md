# 0027 以条款矩阵为唯一验收面；本轮只建框架，取证延后

**Status**: accepted

验收这件事此前散在四处：七张旧单的正文、`docs/GameSpec.md` 的段落、`tests/native/` 里没人能对上条款的用例，以及试玩截图的口头结论。想回答「第 7 节第 11 条到底验没验过」，只能把四处都翻一遍，而且每处的答案都不一样。

原生 Busted 迁移解决了「测试怎么跑」，没有解决「测试对应哪条规矩」。#242 把规格拆成可判真假的条款、按小节分片，矩阵已经存在；#243 要把「矩阵里写了什么」变成「机器能核对什么」，同时把决定记录下来。

## 决定

1. **`docs/acceptance/` 是唯一的验收面**。一条规矩只要没有条款 ID，就等于没有被验收；矩阵是唯一待办面，工单、聊天记录、临时文档里记一笔不算登记。
2. **`docs/GameSpec.md` 是规格本体，不引用工单编号**。规格说「是什么」，矩阵说「验到哪一步」，两者的引用方向只有「矩阵指向规格小节」。
3. **矩阵本身受门禁保护**（`tools/acceptance.lua` 判定，随 fast 车道跑）：分片恰好覆盖规格的 19 个小节、四列取值在封闭词表内、条款 ID 连续不跳号、`blocked` 写明卡在谁、`out-of-scope` 写明理由、已取证行的每个仓库相对路径真实存在、索引的计数由脚本生成且手改会被判红。
4. **两道单向棘轮**（`docs/acceptance/baseline.lua`）：已取证条款数（`evidenced` + `accepted`）只增；fast 与 full 车道发现的遗留测试文件数只减。反方向直接判红，`--update-baseline` 也拒绝写反方向。
5. **证据分三档，取证车道独立**：A 级走业务入口黑盒断言、B 级时序探针、C 级试玩观察；A 级断言住在 `tests/native/spec/`（`spec` 车道，随 full 跑，不计入遗留测试）。口径见 [证据分级](../acceptance/evidence-levels.md)。三档说的是「怎么取证」，与 [ADR-0028](0028-solo-clear-on-shared-world.md) 的四类证据（正常流程、失败流程、退出重进、存档恢复）是两条正交的轴：一栏覆盖范围里的每条条款，再按三档之一取证。
6. **本轮只建框架，取证延后**。`docs/acceptance/` 里的条款绝大多数保持 `unverified` / `blocked`；本轮只把**一条真实条款**（`7-11` 商店限购）用一条走业务入口的黑盒断言转成 `evidenced`，作为「框架能拦人、断言能落地」的样板。

## 理由

**先建门禁、后铺取证，是因为铺量会把门禁的毛病一起铺开。** 如果先写三百条断言再补门禁，出问题时分不清是断言写错了还是门禁判错了；反过来，门禁先立起来、样板先跑通，后面每加一条断言都自动受同一套规则约束，坏一处红一处。

**取证要等业务代码落定。** 第 12–16 节（精英与首领、图鉴、抽奖机、盲盒、物品基础数据）的业务代码正在并行推进；对着还会动的实现写黑盒断言，改一次实现就要改一次断言，且断言会不知不觉钉住临时实现。等接口稳定再写，断言钉住的是条款，不是当天的代码。

**试玩取证只能整批做。** C 级条款判的是地图里的贴地、净空、遮挡与手感，需要一次连续的试玩会话覆盖一批条款；零散抓单条既费事又不可比，所以整批延后。

**棘轮必须单向，否则「已取证」会悄悄缩水。** 双向可调的基线等于没有基线：算错了就把基线调低，指标永远好看。单向的代价是加遗留测试时必须同时删掉一条旧的（或者新证据走 spec 车道），这正是想要的压力。

## 拒绝的方案

1. **把验收写进工单**：工单会关、会清，关掉之后没有任何人和机器再看得见那条规矩。#242 清掉的七张旧单就是这个的下场。
2. **让 `tests/native/` 的既有用例充当证据**：它们九成是实现自检（断言内部函数与夹具细节），没有条款 ID，删一个内部函数就红一片，条款却一条也没被判定。用它们当证据等于把「实现没坏」冒充成「规矩成立」。
3. **双向基线**：见上，等于没有基线。
4. **本轮铺满取证**：会把门禁与断言一起写错，且对着未定的业务代码写断言。

## 后果

- 新规矩的入口只剩一条：先写进 `docs/GameSpec.md` 的小节，再按 [TEMPLATE.md](../acceptance/TEMPLATE.md) 在对应分片登记条款，然后才可能有代码。没进矩阵的活等于没有。
- 本轮框架能拦下的四种「手滑」——改坏基线、写不存在的证据路径、手改索引、在规格里塞工单号——都有可复现的拦截记录（`tests/native/acceptance_matrix_test.lua` 的夹具用例逐条覆盖；该文件 2026-11-20 迁至 `tests/native/guards/`，路径按当时记录）。
- **延后的批次与恢复条件**（与 #240 的批次表一致）：
  - **D 通关取证**、**E 多人规则组**、**F A 级断言铺开**、**G B 级探针补齐**、**H 旧测试清账**。
  - 恢复条件：D/E 等业务代码（第 12–16 节与多人接缝）合入集成分支、接口稳定之后启动；F 与 G 按分片逐节推进，每转一条 `evidenced` 都顺手抬一次基线；H 与新证据同步进行——只有删掉一条遗留测试才能把 `legacyTests` 降一格。
- 门禁的代价：fast 车道多一次全量分片扫描（19 份分片、500 余条款，亚秒级）；spec 车道随 full 跑，不影响日常耗时。
- 已知限制：证据等级本身写错（把只能 C 级的条款标成 A）机器拦不住，靠评审，判据写在 [证据分级](../acceptance/evidence-levels.md) 第六节。
