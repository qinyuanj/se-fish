# 0012 以真实模块职责建立六层架构与依赖门禁

**Status**: accepted

`se-fish` 的三个运行端目录由宿主工作区约束，不能把 `client`、`server`、`common` 直接当成高低层。此前只把三端 `packages` 标为最底层，未分类、反向依赖和循环依赖没有可执行约束。`fs-monopoly` 已证明分层声明、架构图和门禁可以共用一份真源，但其七层职责不适用于本图。

决定：

- 采用 [架构分层与依赖门禁](../architecture.md) 的六层：入口、应用流程、展示与运行端支撑、共享规则与业务状态、配置内容、官方包。
- 层归属只引用真实模块和现有命名空间。`tools/arch_policy.lua` 是唯一声明，投影到 `policy.edn` 的 `:levels`，测试阻止漂移。
- 门禁进入现有 Busted fast/full 车道，拒绝未分类、反向依赖、跨端加载、模块环和命名空间投影环。`server/_trigger` 仍排除。
- 官方包内部环豁免，包含包外业务的环不豁免。
- 技能行为通过 `server/main.lua` 注入协作管理器；挥砍登记拆到 `server/SwingRegistry.lua`，武器特效直接调用 `MgrModifier`，不为旧技能环设置白名单。

备选方案（拒绝）：

1. **照搬 `fs-monopoly` 七层**：本图已有三端运行约束与大量 SE 管理器，层名和目录不能一一对应，搬文件只会制造假边界。
2. **保留三端并列加 packages 两层**：无法区分共享规则、引擎适配和入口组装，也不能防止业务反向依赖。
3. **给技能投影环和上行边登记豁免**：通过 `BehaviorServices` 与 `SwingRegistry` 可以局部破环，无需保留例外。
4. **把 `common.Util` 声明为纯工具底层**：它实际依赖 `REUtil` 并使用引擎服务，声明会与职责不符。

后果：

- 新独立根模块必须显式归类；已有命名空间的后代继承归属。
- 静态依赖方向与架构图可自动复核，入口注入和 RemoteEvent 仍需行为测试约束。
- 官方包仍属业务范围并位于最底层，ADR-0010 不变；包内部环的豁免不改变质量快照口径。
