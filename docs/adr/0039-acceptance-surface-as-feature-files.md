# 0039 验收面收敛为功能文件：两列条款，状态由证据反推

**Status**: accepted（2026-11-24）

## 背景

到 2026-11-24，`docs/acceptance/` 的手写面约 7,500 格：19 份分片里 525 条条款 × 7 列，加一份 684 行的实现覆盖表。两个代价同时存在。

- 新增一条条款要同步规格、分片、索引生成块和覆盖表；改错一列，门禁报的是列名，不是条款。
- 矩阵只记「验到哪一步」，不记「打开编辑器之后从哪个入口进、点什么、看什么算过」。C 级条款卡在「需编辑器试玩取证」，缺的正是这一层。

覆盖表也在漂移：它记录代码落点与关联测试，但关联测试是实现自检，不是条款证据；同一件事被写了两遍，读者要同时读矩阵与覆盖表才知道一条条款到底算什么状态。

## 决定

1. **条款只留两列**：ID 与文案。证据等级写成文案末尾的 `（A）`、`（B）` 或 `（C）`。组、执行者、状态、证据 / 理由四列删除。
2. **状态由 `tools/acceptance.lua` 的 `M.infer` 反推**，人不再手写：
   - A/B 级条款的 ID 出现在 `tests/native/spec/` 或 `tests/probes/` 的文件正文里，即 `evidenced`。
   - C 级条款只认 `evidence/*/session.md` 里标 `✅` 的对照行。
   - 没有证据的 C 级条款是 `blocked`，其余是 `unverified`。
3. **证据路径同样反推**：命中该条款号的文件就是它的证据，不再由人抄进证据列。
4. **删除两处冗余账**：`docs/acceptance/coverage.md` 与 `docs/acceptance/handover.md` 的盘面、完成判据表。`baseline.lua` 只保留已取证棘轮，遗留测试棘轮删除。
5. **门禁瘦到五项**：ID 与结构（19 节分片、ID 连续、等级后缀）、禁用措辞、索引一致、证据文件不引用矩阵没有的条款号、已取证只增。
6. **每份分片补三节驾驶说明**：`## How to get to it (user POV)`、`## Driving it with tools/cli.lua`、`## Gotchas`。第 4 节先做，作为试玩整批取证（#267）的前置。

## 理由

**状态是证据的投影，不是人的判断。** 一条条款有没有证据，机器能从文件正文里读出来；人再抄一遍只会抄错。删掉状态列后，补证据的动作从「改分片 + 跑 --write + 抬基线」变成「写一条正文带条款号的断言」，门禁自己看到状态变化。

**证据与代码落点是两个问题，不该挤在一张表里。** 覆盖表的关联测试只证明「这段代码有测试守着」，不证明条款成立；它最有用的一列（代码落点）在模块改名与拆分后频繁漂移，维护成本高于收益。条款证据由断言正文表达后，落点随断言文件名与 `require` 走，不再另抄一份。

**驾驶层是缺口，不是冗余。** 矩阵回答「验没验过」，不回答「怎么验」。C 级条款的阻塞原因正是缺这一层；把入口、驱动命令与坑写进分片，验收才可复现。

## 实测

- 反推与迁移前的 525 条手写状态逐条比对，0 条不一致：156 `evidenced`、52 `blocked`、317 `unverified`。
- 反推覆盖 156 条已取证条款；新增的 5 条（#276、#277）同样命中。
- 迁移只改列，不碰文案：525 条条款的 ID 与文案逐字比对，0 条差异。
- 两处正文提到却不构成整体取证的条款（9-05 只取证抢救段、11-20 只在注释里写「不归本单」）登记在 `M.INFER_EXCEPTIONS`；gate 用例盯着例外仍然有命中。
- 条款号边界收紧后，日期 `2026-11-04` 与工单引用 `#249-10` 都不再误命中。

## 拒绝的方案

1. **整体替换为另一套验收工具**：迁移成本高于收益，且现有条款 ID 已被规格、测试与台账引用。
2. **保留状态列，只删组与执行者**：状态仍要被手抄一遍，漂移的根因没解决；执行者与等级在 A/B 与 C 的划分里本来就重复。
3. **把代码落点写进每条条款**：模块改名频繁，条款行会被改动淹没；落点改由断言的 `require` 与文件路径表达。
4. **用证据文件的任意提及判定取证**：会把「注释里说不归本单」和「只取证了一段」算成已取证；因此收紧到 C 级只认 `✅`，并保留两条例外。

## 后果

- 新增条款只需改规格与分片一行，然后跑 `acceptance --write`；补证据不再改分片。
- `acceptance --infer` 成为调试入口：逐条列出反推状态、证据路径与孤儿条款号。
- 覆盖表删除后，需要看某段代码有没有测试守护时，读 `tests/native/spec/` 的断言：文件名与正文都带条款号。
- 已取证棘轮继续单向：基线只能抬，反方向 `--update-baseline` 退 2。
- 门禁不再检查「规格与分片里是否出现工单编号」：这条规则由 [TEMPLATE.md](../acceptance/TEMPLATE.md) 的评审条款承接，机器不再拦截。
