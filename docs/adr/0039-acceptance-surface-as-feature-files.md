# 0039 以功能文件为唯一验收面：两列条款，状态由证据反推

**Status**: accepted（2026-11-24；取代原 ADR-0027）

验收口径此前一度散落在工单、规格段落与零散测试里；随后建立的七列条款矩阵与实现覆盖表又引入约 7,500 格手写维护面，且缺乏「打开编辑器后如何复现验收」的驾驶说明。本 ADR 确立唯一验收面、三档证据与两列反推形态。

## 决定

1. **`docs/acceptance/` 是唯一验收面**：一条规矩没有条款 ID 就等于未被验收；工单、聊天记录、临时文档不算登记。`docs/GameSpec.md` 是规格本体，不引用工单编号，引用方向仅为「分片指向规格小节」。
2. **证据分三档**（与 [ADR-0028](0028-solo-clear-on-shared-world.md) 的四类覆盖范围正交，细则见[证据分级](../acceptance/evidence-levels.md)）：A 级走业务入口黑盒断言（`tests/native/spec/`）、B 级可重跑时序探针、C 级编辑器试玩观察（`evidence/*/session.md`）。
3. **条款只留两列**：ID 与文案；证据等级写成文案行尾后缀 `（A）`、`（B）` 或 `（C）`。
4. **状态与证据路径由 `tools/acceptance.lua` 的 `M.infer` 反推**，不手写：
   - A/B 级条款号出现在 `tests/native/spec/` 或 `tests/probes/` 正文即 `evidenced`（仅注释提及或部分覆盖者显式登记在 `M.INFER_EXCEPTIONS`）；
   - C 级条款只认 `evidence/*/session.md` 里标 `✅` 的对照行；
   - 无证据的 C 级为 `blocked`，其余为 `unverified`。
5. **不维护独立覆盖表**：删除原实现覆盖表，代码落点由断言文件名与 `require` 表达；`baseline.lua` 只保留「已取证条款数只增」单向棘轮（反向 `--update-baseline` 退 2 拒绝）。
6. **门禁守五项**（随 fast 车道运行）：19 节分片结构与 ID 连续/等级后缀、禁用措辞、索引生成块一致、证据文件无孤儿条款号、已取证只增。
7. **每份分片带三节驾驶说明**：`## How to get to it (user POV)`、`## Driving it with tools/cli.lua`、`## Gotchas`。

## 理由

- **状态是证据的投影**：机器能从断言正文与试玩记录直接读出状态，手抄只会漂移；补证据变为「写带条款号的断言」，不再手改分片。
- **驾驶层是 C 级试玩的缺口**：矩阵不仅回答「验没验过」，还提供可复现入口、驱动命令与避坑说明。

## 拒绝的方案

1. **把验收写进工单**：工单关闭后规矩即消失，机器无法校验。
2. **让既有实现自检充当条款证据**：无条款 ID、钉住内部实现，不能证明规矩成立。
3. **保留手写状态列或独立覆盖表**：同一事实写两遍必然漂移；模块改名时覆盖表维护成本高于收益。
4. **用证据文件的任意提及判定取证**：会把注释引用或局部测试误判为整条已取证，因此收紧条款号边界、C 级只认 `✅` 并显式登记例外。

## 后果

- 新增条款只改 `docs/GameSpec.md` 与对应分片一行，再跑 `lua tools/cli.lua acceptance --write`；补证据不再改分片。
- `lua tools/cli.lua acceptance --infer` 为逐条反推调试入口。
- 证据等级是否标错（把只能 C 级的标成 A）与规格/分片不写工单号由评审把关（见 [TEMPLATE.md](../acceptance/TEMPLATE.md)）。
