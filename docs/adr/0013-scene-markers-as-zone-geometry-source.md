# 0013 区域几何以场景区域标记为准

**Status**: accepted

美术重做七区场景后，区域几何不再整体平移：各区相对位移不同、虾池单独重做、礁石岛只剩假山石群，旧灰盒与 `GameCfg` 手写坐标同时失真。继续在 `GameCfg.Zones[*].Scene` 与 `GameCfg.Water.Zones` 里维护坐标，需要每次美术改动都人工同步，而且派生量（`AirCombat`、`BossArena`、`Flight.FallbackBounds`、航线目的地）各自引用一份，改一处漏一片。

决定：区域几何的唯一事实源是场景里的**区域标记**（每区边界盒、可钓水域盒与水面高度、安全落点、去/返程摆渡点、烧烤点、抽奖点、鱼饵刷新点），运行时按名读取；`GameCfg` 只保留数值与内容配置，不再存区域坐标。标记沿用既有命名（`Z3_Water` 等），保留现有按名解析代码的入口。旧灰盒几何删除，不再作为任何判定依据。爆炸半径等票面数值（火箭筒 5 米、烤糊 3 米）不属于区域几何，不受影响。

备选方案（拒绝）：把实测坐标写回 `GameCfg` 一次性止血——本轮即可恢复，但下一次美术改动会重演同样故障；保留灰盒作为隐藏载体——省一轮重建，但灰盒与新地形重叠处仍有双重碰撞与穿帮风险。

后果：美术摆标记成为区域交付的一部分，缺标记的区无法验收；`GameCfg` 末尾的折返变换退役；`docs/adr/0003-shrimp-pond-unified-zone-template.md` 的统一模板口径随之作废。决定记录见 [#65 美术重做后的区域重对齐](https://github.com/qinyuanj/se-fish/issues/65)。
