# 0013 区域几何以场景区域标记为准

**Status**: accepted

美术重做七区场景后，区域几何不再整体平移：各区相对位移不同、虾池单独重做、礁石岛只剩假山石群，旧灰盒与 `GameCfg` 手写坐标同时失真。继续在 `GameCfg.Zones[*].Scene` 与 `GameCfg.Water.Zones` 里维护坐标，需要每次美术改动都人工同步，而且派生量（`AirCombat`、`BossArena`、`Flight.FallbackBounds`、航线目的地）各自引用一份，改一处漏一片。

决定：区域几何的唯一事实源是场景里的**区域标记**（每区边界盒、可钓水域盒与水面高度、安全落点、去/返程摆渡点、烧烤点、抽奖点、鱼饵刷新点），运行时按名读取；`GameCfg` 只保留数值与内容配置，不再存区域坐标。标记沿用既有命名（`Z3_Water` 等），保留现有按名解析代码的入口。旧灰盒几何删除，不再作为任何判定依据。爆炸半径等票面数值（火箭筒 5 米、烤糊 3 米）不属于区域几何，不受影响。

2026-11-04 场景回退后的重做补充了标记合同：边界由四面空气墙的位置与尺寸解析，点位由具名标记解析；不规则水岸用不重叠的轴对齐水域标记覆盖，不拿整片 `深水` 或美术装饰的包围盒代替可钓水域。玩法只依赖稳定的 `Z*` 名称，摆渡车、烤架等美术件不是运行时查找入口。每轮试玩启动时统一解析并校验，缺标记、重名或尺寸非法明确失败；该轮内使用快照，编辑后的坐标在下轮试玩生效。标记先建齐，消费方迁移完成后再删旧几何与配置，避免中间版本仍读旧坐标。

06 礁石岛在地形补齐前保留临时可行走地面，不用假山石包围盒冒充正式岛面。空场景文件夹可以清理，但以回读无子项且没有运行时按名引用为前提；不能归组的地形不因此强搬或删除。

备选方案（拒绝）：把实测坐标写回 `GameCfg` 一次性止血——本轮即可恢复，但下一次美术改动会重演同样故障；保留灰盒作为隐藏载体——省一轮重建，但灰盒与新地形重叠处仍有双重碰撞与穿帮风险。

后果：美术摆标记成为区域交付的一部分，缺标记的区无法验收；`GameCfg` 末尾的折返变换退役；`docs/adr/0003-shrimp-pond-unified-zone-template.md` 的统一模板口径随之作废。摆渡目的地也必须从标记读取，不能只迁移上船点。决定记录见 [#65 美术重做后的区域重对齐](https://github.com/qinyuanj/se-fish/issues/65)。
