## 工具链能力缺口：编辑器 SDK 全树枚举故障

**已定论：本轮不修，接受绕过（2026-10-14，[决策单 #100](https://github.com/qinyuanj/se-fish/issues/100)）。动场景前先读本节。**

- **现象**：SDK 内部 `WorldService.lua:535` 的 `tryBuildReflectClass` 把 Python/MessagePack 桥接字符串（`u'WaterUnit'`、`u'Script'`）直接当 Lua 表键写进 `REFLECT_CLASS_CACHE`，抛 `table index can only be a string/integer/real.`。
- **调用侧无补丁点**：`~/.eggitor/cli/editor-cli.exe` 是单文件打包，`editor-unit` 的 Lua 载荷在 exe 内；即便改也会被 `editor-cli env-res` 更新覆盖。即"修复"只剩官方 SDK 一条路。
- **后果**：整个 `editor-unit` 子命令族不可用。其 `find_unit → all_units → getUnits` 先建全量索引，所以**即使已持有正确 UnitId 也失败**（`get` / `get-property` 实测 `EDITOR_UNIT_SCAN_FAILED`，`transform` / `set-property` / `reparent` / `rename` / `delete` 同族推断失败）。
- **不修的理由**：官方资源通道最新仍为 `editor_cli_* 0.20.2`，没有含修复的版本可升；而绕过路径已覆盖本轮全部操作类型。本缺陷不走官方反馈渠道（2026-10-14 决定），修复到达以版本变化为准。
- **复查触发**：本机 `editor-cli --version` 与 `0.20.2` 不同时，重开决策单 #100 评估是否换回原路径。`env-res list` 的 `latest` 变化只作背景信息。
- 证据：[影响面取证 #101](https://github.com/qinyuanj/se-fish/issues/101)、[故障复现](https://github.com/qinyuanj/se-fish/issues/65#issuecomment-6109717681)。

### 绕过合同（四条硬边界）

1. 不用 `editor-unit` 子命令做任何按 ID 的操作，一律走 `editor-cli exec` + Lua 直调公开 Unit API。
2. 不用 `World:GetDescendants()` / `World:GetChildren()`（World 包装对象没有 `GetChildren`）。
3. 不枚举 `Script` / `PresetLink` **类型本身**（`GetUnitsByUnitType` 仍报 535）；这两类经已知父节点的 `GetChildren` 访问。
4. 同名递归查找必须限定父节点：**递归能力只在 `World` 服务上**，同名多对象（如 7 个 `铁艺弯钩`、7 个 `设施`）只返回第一个命中。
   2026-10-14 修正（#65 P2 实测）：`World:FindFirstChild(name)` 递归且**不需要**第二个参数；
   `Unit:FindFirstChild(name)` 的 meta 只有 `name` 一个参数，**只匹配直接子级**，多传的 `true` 被静默忽略
   （`zone:FindFirstChild('大地板', true)` → nil，`zone:FindFirstChild('地块'):FindFirstChild('大地板')` → 命中）。
   写探针要递归时手工栈遍历，不要指望第二个参数。

边界内经 `exec` 已实测可用：非 `Script`/`PresetLink` 的类型枚举、非根子树 `GetChildren` / `GetDescendants`、任意层级 `GetProperty` / `SetProperty`、`World:CreateUnit`、`SetPosition` / `SetRotation` / `SetScale`、`SetParent`、地图保存与重开回读。`SetTRS` 有旋转写入异常，优先用三个独立接口（[#65 记录](https://github.com/qinyuanj/se-fish/issues/65)）。

**取证口径**：绕过的探针脚本放 `tests/probes/`（手工探针，不入任何车道），不放 `%TEMP%`；一次性脚本只用于临时试验，正式证据要可重跑、可 diff。

**沙盒能力边界（2026-10-14，#65 P2 实测）**：`exec` 的编辑器沙盒里 `require` 存在但不可用
（`sdk.common.lua:830: attempt to call a nil value (field 'require')`），`io` / `os` / `loadfile` / `package` 全部缺席；
所以探针**不能**加载 `common/GameCfg.lua`、也读不了外部数据文件，任何配置派生的清单必须离线生成后以字面量嵌入
（做法见 `tools/gen_config_anchor_probe.lua` + fast 车道同步守卫）。另：`EffectUnit` 不是 `SpaceUnit`，
`GetPosition()` 回读 nil，不能把 nil 当坐标 0。

**附带事实（与本节故障无关）**：编辑器 API 没有任何 Unit 同级排序成员（`api search-editor` 检索 `order` / `sort` / `index` / `sibling` 只命中 DataStore 的排序存储）。所以"分组按数字升序显示"即便修好 535 也拿不到排序 API，只能靠命名 / 摆位表达，或改判期望。

## 高风险：存在能力缺口或无法在试玩中验证

### 1. 非人形鱼 / 首领的模型与动画

**MVP 已定论（静态模型路线）**

- MVP（#27 鱼种表收敛）收敛到鱼塘 6 种普通鱼：罗非鱼、鲤鱼、刀鱼、鲈鱼、鲶鱼、金鱼，全部用官方静态模型（`7000557`、`7000552`、`7000545`、`7000551`、`7000553`、`7000544`），Kinematic 程序移动。精英鱼、首领、哥斯拉、三头鲨、翼龙为 MVP 范围外。
- `AnimatedUnit : WorldUnit`（`:5040`）不带 Controller，没有 `Health` / `TakeDamage` / `MoveTo` / `Died`；鱼的血量、受击由 `MgrFishCarrier` 自研（见 §8）。
- **仍未验证**：非人形带动画 FBX 导入（精英鱼阶段需要时再做原型，预期偏悲观）。官方模型库无鳗、哥斯拉、三头鲨；动作目录全是角色动作。

### 2. 鱼的移动与 AI

**MVP 已实现 Kinematic 程序移动（#42）**

- 鱼逃脱时由服务端直接设 `BodyType = Kinematic` + 逐帧更新 `Position`，朝最近水区直线跑；只按 `(x,z)` 判入水，入水销毁。不依赖 `PathfindingService`。
- MVP 范围内鱼不主动攻击玩家、不巡航、不跃起。
- **仍为难点（精英鱼 / 首领阶段）**：
  - `PathfindingService`（`HasNavMesh` / `HasDynamicNavMesh`）只解决地面行走；飞行（白头鹰、风神翼龙）、跃起落点 AOE、绕岛巡航后跃出咬人、随机翻滚仍需自写轨迹。
  - 性能：逻辑帧 30 Hz，服务端逐帧驱动；8+ 玩家 × 每人多条活鱼时需做数量上限与追踪降频（`MgrFishUnit` 已有在逃数量上限）。

### 3. 水体判定

**已实现（MVP #35 / #42 / #12）**

- 水圈（`WaterCircle1/2`）是水材质渲染的 `WorldUnit`，`CanQuery=true` 但命中几何为空——水中心垂直射线依次撞 `TGUnitFish` 触发器顶面（y≈6.77）和大地板（y=2.0），全程碰不到水圈。射线方案不可行。
- **已定论方案**：`MathWaterJudge`——每个水区配 `{Center, HalfXZ, SurfaceY}`，对 `(x,z)` 做轴对齐矩形判定，`pos.y ≤ SurfaceY` 算入水。纯数学，300 次调用仅 0.12 ms（对比射线 6.21 ms）。
- 鱼逃脱时只按 `(x,z)` 判入水区，入水即销毁（`MgrFishUnit`）；抛竿落点判定同一套（`MgrCast`）。
- 仍未实现：空气墙挡游泳（MVP 范围外）。

### 4. 付费闭环（金豆 / 乐园币 / 广告 / 盲盒）

**MVP 只完成金币体系（#47 / #48），付费闭环未实现**

MVP 实现了金币 HUD、GM 发放（调试开关）、钓场商店（鱼竿 / 蚯蚓）、向钓鱼佬 NPC 喂食换金币。`CommodityService`、`AdvertisementService`、`MemoryStore`、`DataStore` 均尚未接入。以下难点维持原状：


- 能力：`CommodityService`（17 函数 / 5 事件，`:3925-4040`）；`AdvertisementService:ShowRewardedVideoAd(player, goodsId, successEvent, failEvent, adTag)`（`:3607`）；邮件系统可发"游玩奖励"类商品。
- 难点：
  - **无订单 ID**：`GoodsPurchaseCompleted(goodsId, goodsNum, player)` "当前没有公开订单 ID"，官方教程明说不能用 `UserId..goodsId` 做发货防重键（`<站点>/lua/20-platform-services.html`）。在服务端监听该事件发货，幂等要自己设计。
  - **购买无取消 / 失败回调**：5 个事件里没有，`ShowGoodsPurchasePanel(player, rawGoodsId, showTime)` 返回 void。"支付期间暂停复活倒计时，取消后恢复"没有事件可挂，只能超时兜底。`showTime` 的语义未说明，需实测。
  - **广告在编辑器内不可验收**：须服务端调用；编辑器 / 本地调试"可能无回调、无 UI 表现或直接静默失败"（`<站点>/game_api/service/AdvertisementService.html`）。`failEvent` 也不保证触发，同样要超时兜底。
  - `goodsId` 来自商业化后台，后台文档不在公开站点。API 无价格 / 货币 / 盲盒 / 抽奖接口，盲盒的随机与发奖只能写 Lua，支付环节才可能走商品。
  - 盲盒货币已于 2026-09-29 改为金豆（单抽 10、十连 90），旧金币结论作废。
  - 需要一张已发布的测试图。MemoryStore 明文未发布不可用（`UnpublishedPlace=102`，`:3263`）；DataStore 错误码无"未发布"项，教程默认测试地图可真实读写（推断）；商品未查到。

### 5. 存档体积与可靠性

**MVP 阶段无存档（纯内存）**

MVP 数据全部在 `MgrPlayerData` 内存态，离线即清，`DataStoreService` 尚未接入。以下为上线前必须解决的难点，状态未变：

- 能力：`DataStoreService`（`GetDataStore` / `GetGlobalDataStore` / `GetOrderedDataStore`，`UpdateAsync` CAS，版本历史），全异步，须在 `Task:Spawn` 内调用；`game:BindToClose` 关服前留 30 秒。官方 fishing-demo 的做法：`pcall` 重试 + 会话锁 + 30 秒自动存档 + Attribute 同步客户端。
- 物品不叠加，每条鱼带个体倍率与烤制倍率；道具栏 8 + 背包 40 + 旧盲盒“不受背包上限”规则已废弃；2026-09-29 改为满格落地并计入全区 200 件预算。仍需对图鉴、操作记录与全字段存档做容量和写频台账。
- `ValueTooLarge=123` 与四层限流错误码（单局队列 / 单键 / 单服务器 / 全服务器）都无数值（`:2932-3002`）；写入必须合并、排队；`pcall` 只能靠错误信息字符串区分。
- 离线续存项多：所在钓鱼区与坐标、濒死 / 死亡标记、虚弱剩余时间、药水次数、图鉴最大重量、新手任务进度。
- 0917 新增 `Game.ServerRestartScheduled`，与常驻房间的存档时机直接相关，本地 API 声明尚未包含。

## 中风险：有能力，但实现量大或有坑

### 6. 全服纪录

可行。`OrderedDataStore:GetSortedAsync`（`:1666`）即排行榜用途，**值必须为整数**（错误码 411，`:2998`），鱼重量需放大取整后存。难点在约 100 种鱼的键设计、写限流，以及跨服务器刷新（`MessageService:PublishAsync`，单条 ≤ 1 KB，尽力而为不保证送达）。

### 7. 玩家状态改造

**血量 / 饥饿 / 死亡 / 复活已实现（MVP #53）**

- 血量上限 300、饥饿上限 300，由服务端 `MgrVitals` 单一权威管理；目标是掉血统一走 `ApplyDamage(player, amount)`；2026-09-29 静态核查仍有鱼战斗直接 `TakeDamage` 的旁路，需统一后实现濒死。
- 血量宿主是角色 `Controller.Health`（M0 台账 §4 实测）；饥饿是服务端内存态，每秒推进一次（`World:GetServerTime()` 整秒）。
- 死亡：订阅 `Controller.Died` + `Update` 轮询 `Health ≤ 0` 双路兜底，只记一次；复活用 `Update` 轮询同一 `Controller.Health` 从 0 回正（而非 `CharacterAdded`，因引擎复活不换角色）；超时兜底调 `Controller:Reborn()`。
- 自动复活延时已在编辑器【死亡规则】面板配置（M0 已核），无需代码控制。
- 原生血条由 `CoreGuiType.Health` 关掉；HUD 用环形进度 EUI 节点（`official://image/30013`）。
- **仍未实现（MVP 范围外）**：濒死锁血（1 血抢救）、PK 区 / 安全区 / 小队免伤、变大药水 3 倍缩放副作用、风神之翼、哥斯拉变身。
- `TakeDamage(damage)` 无来源参数，脚本伤害无原生过滤，PK 区等仍需服务端自判。阵营 API 废弃情况不变（0723 / 0805）。`EggyUnit:SetScale` 3 倍碰撞副作用未验证。

### 8. 举鱼

**已实现（MVP #41 / #42），核心接缝已实测**

- **双单位方案定论**（#25 台账 §1，M18 复证）：鱼本体是带 `Liftable` 的 `WorldUnit`，受击体是 `EggyUnit(EnableController=true)`，两者绑定同位。`WorldUnit` 没有 `Controller`（`.Controller` 恒 nil，赋值报 `cannot access an internal table/userdata`）；`EggyUnit` 没有 `Liftable`——引擎里两件事落在两个不同单位类型上，无法合并。
- **抓举**（#41）：上岸即由服务端调 `Lift(鱼本体)`；`EggyController.OnLiftBegin` 不触发（官方明说），改听鱼本体侧 `WorldUnit.OnLiftedBegin`，回调里立刻建骨骼挂点（`SkeletalSocketMount`）并把鱼挂进去；举着期间不改 `BodyType`，引擎已切 Kinematic。
- **放下 / 逃脱**（#42）：主动放下、`OnLiftedEnd`、持有者死亡走同一条幂等 `Release`——回世界、落在玩家面前、Kinematic 朝最近水区跑；只按 `(x,z)` 判入水，入水即销毁无收益。不调 `Throw`。
- **碰撞隔离**：鱼本体与所有玩家、其他鱼本体 / 受击体互加 `AddNoCollisionPairWithUnit`，防漂移 / 顶飞 / NaN（M18-2 实测）。
- `Attachment`、`RigidConstraint`、`WeldConstraint` 均不可行（原因不变，见原条目）；父子层级备选方案未再验证，当前方案已稳定无需探索。

### 9. 高频输入

冲锋枪 0.1 秒连发、收线狂点，都是每人每秒约 10 次 RemoteEvent。频率与包大小上限在本地注释、官方页、教程里都没有数值；每次只能带一个 payload，且不支持直接传 `CFrame`（`:1995-2021`）。客户端按时间窗聚合，服务端用 `World:GetServerTime()` 校验 CD 与次数上限，命中用服务端 `PhysicsService:Raycast`（目标须 `CanQuery` 且碰撞组允许）。

### 10. 摆渡

`SeatUnit` / `Seated` 状态存在；"站在船上被带走"依赖物理摩擦，不可靠。建议倒计时结束时把船上 Trigger 内的玩家直接传送，船只做表现。`TeleportService:TeleportAsync(mapId, players)` 是跨地图传送，可作"七区拆成多张图"的退路，但会拆散同房玩家，搭便船与返程的语义要重做；`ChangeServerAsync` 等跨服接口在编辑器内返回 false / nil，不可测。

### 11. 单图七区的规模

整图容量、单位总数上限无数值：只有同级子组件上限（多为"不限"）与资源大小（图片 ≤ 3 MB、1920×1080，音频 ≤ 1 MB / 60 秒）。平台提供 AOI / Streaming（`World.AOIType`、`StreamingMainRadius`、`BasePart.Persistent`，0820 / 0917 日志）。常驻房间里"丢弃物永不消失"是无界增长，必须加总量上限与回收。场景用 `IsStaticOptimization`，注意标记后脚本查不到该单位。

### 12. 常驻房间

世界模式模板支持，手册只有定性表述"随进随出、可容纳更多玩家"（`<站点>/newbie.html`）。0820 更新后【实时共建】多人试玩支持其他玩家随时加入。房间人数上限无数值（API 无 `MaxPlayers`；`SpawnLocationUnit.Capacity` 是单个出生点容量），可能在编辑器【规则 → 匹配和匹配参数规则 / 乐园岛匹配规则】里配（推断）。

### 13. 分享任务按钮

当前公开 API 不支持。`SocialService` 只剩队伍查询（`:4585-4600`）；`PromptGameInvite` / `PromptLinkSharingAsync` 及其事件在 0723 日志中废弃，官方教程明说"不要照搬旧示例中的分享或邀请函数名"。需改设计或向官方申请。

## 低风险：有直接对应能力

| 需求 | 能力 |
|---|---|
| 鱼线 | `LinkEffectUnit.EndPosition` + 官方特效 5379"连线-绳子"，客户端逐帧更新终点；0827 新增 `EndBindUnit` |
| 头顶文字泡、NPC 交互 | `SceneGui` 把 EUI 节点挂到单位插槽；无 ProximityPrompt，距离检测自写 |
| 血量球 / 饥饿球 | `EUIProgressTimer` 环形进度 |

| 通关成就 | `ArchiveService:SetAchievementProgress` / `AchievementComplete` |
