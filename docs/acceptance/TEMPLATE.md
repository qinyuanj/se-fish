# 条款模板与新增条款的受控入口

> 本文件规定 `docs/acceptance/` 下条款行的唯一格式、七列必填项、编号与重排规则，以及什么样的行**不算**合法条款。
> 小节索引见 [README.md](README.md)；可照抄的写法见示范样本 [09-multiplayer-rules.md](09-multiplayer-rules.md)。
> **Clause / 条款**：_Avoid_: 条目、需求点、checklist、item

## 一、什么时候必须走这个入口

规格已经写了、但矩阵里还没有判定入口的规则；试玩、代码走查或评审里发现的缺口；以及拆得不够细、需要拆成两句的老条款。登记一律走本入口，不要只在工单、聊天或临时文档里记一笔。矩阵是唯一待办面，没进矩阵的活等于没有。若该节已贯通（`tools/acceptance.lua` 的 `M.COVERAGE_SECTIONS`），同时在[实现覆盖表](coverage.md)登记该条款的代码落点，否则门禁判红 `coverage_clause_missing`。

## 二、可复制的条款行

### 2.1 通用分片

表头与分隔行照抄，列顺序与列名一字不差：

```markdown
| ID | 条款 | 组 | 执行者 | 证据等级 | 状态 | 证据 / 理由 |
| --- | --- | --- | --- | --- | --- | --- |
```

数据行模板（`n` 换成小节号，`NN` 换成两位序号）：

```markdown
| n-NN | 一句话陈述：谁在什么条件下做什么，结果是什么 | 规则 | agent | a | unverified | — |
```

需要试玩观察的条款不进主表，另起 `## C 级（试玩取证）` 小节，用同一套表头；该小节的条款状态写 `blocked`，理由写 `卡在：需编辑器试玩取证（业务代码完成后整批进行）`。

### 2.2 §9 这种三组分片

小队、PK、抢救这类条款，契约与规则必须物理分开成三张表（`## 契约` / `## 规则` / `## 功能`），每张表都重抄上面那行表头与分隔行。这类分片若还有 C 级条款，再按 2.1 另起 `## C 级（试玩取证）` 小节——那时它一共四张表，§9 就是。功能组随依赖排期，状态写 `unverified`，不写成出界。新增一条玩法判定时加进 `## 规则` 表，不要把三组混回一张表；改组时把整行搬到目标表，不要在两处留副本。

## 三、七列必填项

七列缺一列都不算合法条款。

| 列 | 允许值（封闭词表） | 写法 |
| --- | --- | --- |
| ID | 节号-两位序号，如 9-07 | 节号不带前导零；同一文件内从 01 连续递增，不跳号、不重复 |
| 条款 | 一句话 | 谁 + 在什么条件下 + 做什么 + 结果；一条只判一件事 |
| 组 | 契约、规则、功能 | 三选一，语义见 3.1 |
| 执行者 | agent、人、试玩、平台 | 四选一，语义见 3.2 |
| 证据等级 | a、b、C | 三选一，语义见 3.3 |
| 状态 | unverified、evidenced、accepted、blocked、out-of-scope | 五选一；本轮新增条款默认 unverified；见 3.4 |
| 证据 / 理由 | 由状态决定 | 按第四节写；没有证据就写一个全角破折号（—） |

### 3.1 组的语义

- **契约**：跨模块、跨会话必须成立的约定——存档形状、幂等、恢复路径、服务端权威、接口接缝。验收形态多为 b 级时序探针。
- **规则**：玩法数值与判定——伤害、倍率、上限、优先级、互斥结算。以 a 级可断言为主。
- **功能**：需要新建的系统或界面（含第一版可能不做的）。例如小队系统与队伍界面。

### 3.2 执行者的语义

- `agent`：可用代码或脚本重跑取证。
- `人`：需人签署或人工复核。
- `试玩`：必须编辑器试玩观察。
- `平台`：需真实平台（商店、广告、真实设备）。

### 3.3 证据等级的语义

- **a**：黑盒可断言，走业务入口（`server/main.lua` 组合的宿主服务或 `server_runtime` 等）；只断言玩家可观察的结果，不引用实现内部模块。
- **b**：时序探针，覆盖重连、迟到回调、超时、争抢等单次快照看不出来的行为，且必须可重跑。
- **C**：试玩观察——贴地、净空、可读性、手感；必须指到某次试玩验收的会话。

### 3.4 状态的口径

- **规格内没有永久出界**（[ADR-0029](../adr/0029-scope-completeness-and-placeholder-first.md) 第一节）：`out-of-scope` 仍是词表里的合法值，但《渔力全开》的条款一律不用它。功能没做完就写 `unverified` 并排期，不划出范围。
- **唯一允许的 `blocked`** 是需要编辑器试玩或真实渠道的条款：C 级写「卡在：需编辑器试玩取证」，真实渠道事项改记 ADR-0029 的生产开关，条款本身按适配层口径写 `unverified`。
- 状态只在真取证后流转；`evidenced` 必须配一个真实存在的仓库路径。

## 四、「证据 / 理由」列按状态写

| 状态 | 该列必须写成 |
| --- | --- |
| unverified | 一个全角破折号（—） |
| evidenced | 至少一个仓库相对路径，且文件真实存在；多个用顿号串起来 |
| accepted | 同 evidenced，并附人签署：路径（签署：@某人 日期） |
| blocked | 以 `卡在：` 开头，后面写清卡在谁——人、单据、外部系统或试玩场次 |
| out-of-scope | 以 `理由：` 开头，后面写清为什么划出、什么条件下恢复排期。词表保留，但《渔力全开》的条款不用它（见 3.4） |

不允许凭空写 evidenced：路径必须真实存在，且能用第七节给出的命令重跑。

`accepted` 的签署格式固定写成 `（签署：@用户名 YYYY-MM-DD）`，接在路径后面，日期写签署当天；门禁按 `accepted_signature` 判红。

**C 级取证也要落成仓库文件。** 证据列会被门禁按路径解析（只认「带目录分隔符且末段带扩展名」的串），纯会话标识会被判 `evidence_missing`。所以 C 级取证时把会话记录落进仓库，例如 `evidence/<日期>-<会话号>/session.md`（含抓屏清单与观察结论），证据列写 `该文件路径（会话 <会话号>）`：路径满足判据 5「证据路径必须真实存在」，括号里的会话号满足 [证据分级](evidence-levels.md) 对 C 级的语义，两边不打架。

## 五、编号与重排

- 编号 = 节号 + 两位序号。节号与 `docs/GameSpec.md` 的小节一致、不带前导零（`9-07`、`16-04`），文件名里的前导零只属于文件名。
- 新条款追加到所属组表格的末尾，用当前最大序号加一；插到中间时，后面所有条款顺延，不允许出现 `9-07` 与 `9-09` 之间空着 `9-08`。
- 删除条款后立刻重排，保持从 01 起连续。跨文件引用条款一律用 ID（如 `9-17`），不要用「第 3 条」这种位置说法。
- 不新建另一套编号体系：小节号是多少，ID 前缀就是多少。新增分片要同时在 [README.md](README.md) 的清单里加一行。
- 条款增删只改自己那一节的编号，不重排别人的分片。

## 六、这些行不算合法条款

分两档。**6.1 门禁判红**：`lua tools/cli.lua acceptance --check` 每次都会核，机器判得动的都在这里；**6.2 评审判红**：判据在语义里、不在字符串里，机器判不了，只能由人看。写在这里是为了不留死角，不是为了少一条规则。

### 6.1 门禁判红

| 现象 | 为什么不算 | 怎么改 | 门禁的 kind |
| --- | --- | --- | --- |
| 条款行不是恰好七格（缺组、缺执行者、缺证据等级，或多切出一格） | 分不出是补判定还是建系统，也读不出该由哪条车道取证 | 补齐七列；取值见下一行 | `clause_cells` |
| 组、执行者、证据等级或状态写了词表以外的词 | 词表外取值让计数与车道归属失效 | 填 契约、规则、功能 之一；agent、人、试玩、平台 之一；a、b、C 之一；五个状态之一 | `vocabulary` |
| blocked 不写卡在谁 | 外部阻塞会退化成没人推进的待办 | 以 `卡在：` 开头写明具名依赖 | `blocked_reason` |
| out-of-scope 不写理由 | 划出范围就成了暗箱 | 以 `理由：` 开头写明划出原因与恢复条件；本规格直接改成 `unverified` 并排期 | `out_of_scope_reason` |
| 状态写 evidenced 或 accepted，证据列却是 — 或指向不存在的文件 | 无法重跑，等于「我记得做过」 | 补真实路径，或退回 unverified | `evidence_missing` |
| 状态写 accepted，证据列没有 `（签署：@用户名 YYYY-MM-DD）` | 没有人的背书，「验收过」只是自说自话 | 让签署人按第四节的格式补一段，日期写签署当天 | `accepted_signature` |
| 一句话里出现禁用措辞（见下） | 无法判真假 | 改写成可观察的条件与结果 | `vague_wording` |
| 单元格里出现未转义的竖线字符 | 表格列切分被打断，整行解析失败 | 改用顿号或分号；必须保留时写成反斜杠加竖线 | `clause_cells` |
| ID 跳号、重复，或与所在小节号不一致 | 无法稳定引用，引用会随增删漂移 | 按第五节重排 | `id_sequence` / `clause_id` |

**禁用措辞表**（唯一来源是 `tools/acceptance.lua` 的 `M.VAGUE_WORDS`，两处必须一致）：`正确`、`合理`、`符合预期`、`手感要好`、`可行`、`正常`。

只认**独立成句**的用法：词后紧跟句读（`，。；、：！？（）「」`）或到单元格结尾才算命中。`正常流程`、`正常金币`、`连通可行走` 这类构词不算，否则会把已经说清楚的条款一起判红；所以「结果正常。」会被拦，而「鱼顶在头上时模型贴在头顶、不穿进角色身体」不会被拦。判断办法很简单：**删掉那个词之后，这句话还能不能判真假？**能判的留着，不能判的改写。

### 6.2 评审判红（门禁不查）

| 现象 | 为什么不算 | 怎么改 | 机器为什么判不了 |
| --- | --- | --- | --- |
| 一条里塞「a 且 b」两件独立的事 | 部分成立时无法记状态 | 拆成两条 | 中文没有句子边界，「且」可能只是同一件事的两个侧面；正则一拆就把说清了的条款拆碎 |
| 把实现内部模块名写进 a 级条款 | 把实现细节锁死，重构就变红 | 改成玩家可观察的结果，或降为 b 级 | 门禁只看文本，分不出这是模块名还是玩家能看见的名词；口径在 [证据分级](evidence-levels.md) 第一节 |

差与好的对照：「钓鱼手感要好」不可判；「抛竿后到鱼上钩之间，玩家可以按取消键中止本次抛竿，鱼饵不消耗」可判。

## 七、提交前自查

新增或修改条款后，在仓库根目录跑：

```bash
# 各分片解析出的条款行数
rg -c '^\| [0-9]+-[0-9]{2} \|' docs/acceptance/*.md

# 状态列只许出现五个值，有输出即为违规
rg -o '^\| [0-9]+-[0-9]{2} \|.*' docs/acceptance/*.md | rg -v 'unverified|evidenced|accepted|blocked|out-of-scope'

# 编号连续性：人工核对输出里有没有缺号或重号
rg -o '^\| [0-9]+-[0-9]{2} \|' docs/acceptance/NN-*.md | sort
```

四条硬要求：条款 ID 连续不跳号、无重复；组 / 执行者 / 证据等级 / 状态 四列取值都在封闭词表内；blocked 行以 `卡在：` 开头；out-of-scope 行以 `理由：` 开头（本规格不用这个状态，见 3.4）。已贯通小节另有一条：覆盖表里该条款的代码落点必须是非空的真实文件。

上面这些（以及分片是否恰好覆盖规格的 19 个小节、evidenced 行的证据路径是否存在、accepted 行的签署格式、条款里的禁用措辞、规格与分片里有没有工单编号、索引生成块是否被手改）一次性由门禁核对：`lua tools/cli.lua acceptance --check`，它随 fast 车道跑。证据等级与执行者两列的判定口径见 [证据分级](evidence-levels.md)。
