# 条款模板与新增条款的受控入口

> 本文件规定 `docs/acceptance/` 下条款行的唯一格式、编号与重排规则，以及什么样的行**不算**合法条款。
> 小节索引见 [README.md](README.md)；可照抄的写法见示范样本 [09-multiplayer-rules.md](09-multiplayer-rules.md)。
> **Clause / 条款**：_Avoid_: 条目、需求点、checklist、item

## 一、什么时候必须走这个入口

规格已经写了、但分片里还没有判定入口的规则；试玩、代码走查或评审里发现的缺口；以及拆得不够细、需要拆成两句的老条款。登记一律走本入口，不要只在工单、聊天或临时文档里记一笔。分片是唯一待办面，没进分片的活等于没有。

## 二、可复制的条款行

### 2.1 通用分片

表头与分隔行照抄，列顺序与列名一字不差：

```markdown
| ID | 条款 |
| --- | --- |
```

数据行模板（`N` 换成小节号，`NN` 换成两位序号，`等级` 换成 A、B 或 C）：

```markdown
| N-NN | 一句话陈述：谁在什么条件下做什么，结果是什么（A） |
```

证据等级写在文案末尾的括号里。C 级条款仍放在 `## C 级（试玩取证）` 小节，便于一眼看出哪些条款只能试玩取证。

### 2.2 §9 这种分组分片

小队、PK、抢救这类条款，契约与规则必须物理分开成三张表（`## 契约` / `## 规则` / `## 功能`），每张表都重抄上面那行表头与分隔行。分组不再写进条款行：它由小节标题表达。新增一条玩法判定时加进 `## 规则` 表，不要把三组混回一张表；改组时把整行搬到目标表，不要在两处留副本。

## 三、每列的必填项

| 列 | 允许值 | 写法 |
| --- | --- | --- |
| ID | 节号-两位序号，如 9-07 | 节号不带前导零；同一文件内从 01 连续递增，不跳号、不重复 |
| 条款 | 一句话，末尾带等级 | 谁 + 在什么条件下 + 做什么 + 结果；一条只判一件事；最后写 `（A）`、`（B）` 或 `（C）` |

### 3.1 证据等级

- **A**：黑盒可断言，走业务入口（`server/main.lua` 组合的宿主服务或 `ServerRuntime` 等）；只断言玩家可观察的结果，不引用实现内部模块。
- **B**：时序探针，覆盖重连、迟到回调、超时、争抢等单次快照看不出来的行为，且必须可重跑。
- **C**：试玩观察——贴地、净空、可读性、手感；必须指到某次试玩验收的会话。

口径与例子见[证据分级](evidence-levels.md)。

## 四、状态从哪来（不要手写）

状态不是条款行的一部分，由 `tools/acceptance.lua` 从证据文件反推，规则只有三条：

| 状态 | 反推规则 |
| --- | --- |
| `evidenced` | A/B 级条款的 ID 出现在 `tests/native/spec/` 或 `tests/probes/` 的文件正文里；C 级条款出现在某次试玩会话记录的 `✅` 行里 |
| `blocked` | C 级条款还没有任何会话记录标 `✅` |
| `unverified` | 其余条款 |

所以「补证据」不需要改分片：写一条断言、让它的正文提到条款号，状态自己就变成 `evidenced`。C 级取证后，在 `evidence/<日期>-<会话号>/session.md` 的对照表里把该条标成 `✅`。

**正文提到不等于断言了这条。** 如果一条条款只有一段被取证（如 9-05），或证据文件只在注释里说明「不归本单」（如 11-20），就在 `tools/acceptance.lua` 的 `M.INFER_EXCEPTIONS` 里显式登记，并写明原因；gate 用例盯着每条例外仍然有命中。不允许靠改条款文案或删证据文件绕过。

## 五、编号与重排

- 编号 = 节号 + 两位序号。节号与 `docs/GameSpec.md` 的小节一致、不带前导零（`9-07`、`16-04`），文件名里的前导零只属于文件名。
- 新条款追加到所属表格的末尾，用当前最大序号加一；插到中间时，后面所有条款顺延，不允许出现 `9-07` 与 `9-09` 之间空着 `9-08`。
- 删除条款后立刻重排，保持从 01 起连续。跨文件引用条款一律用 ID（如 `9-17`），不要用「第 3 条」这种位置说法。
- 不新建另一套编号体系：小节号是多少，ID 前缀就是多少。新增分片要同时在 [README.md](README.md) 的清单里加一行。
- 条款增删只改自己那一节的编号，不重排别人的分片。

## 六、这些行不算合法条款

### 6.1 门禁判红

| 现象 | 为什么不算 | 怎么改 | 门禁的 kind |
| --- | --- | --- | --- |
| 条款行不是恰好两格 | 分不出 ID 与文案，也读不出等级 | 只留 ID 与文案两格，等级写进文案末尾 | `clause_cells` |
| 文案末尾没有 `（A）`、`（B）` 或 `（C）` | 等级缺失，反推与评审都失去依据 | 补上行尾后缀 | `clause_level` |
| 一句话里出现禁用措辞（见下） | 无法判真假 | 改写成可观察的条件与结果 | `vague_wording` |
| 单元格里出现未转义的竖线字符 | 表格列切分被打断，整行解析失败 | 改用顿号或分号；必须保留时写成反斜杠加竖线 | `clause_cells` |
| ID 跳号、重复，或与所在小节号不一致 | 无法稳定引用，引用会随增删漂移 | 按第五节重排 | `id_sequence` / `clause_id` |
| 证据文件里出现矩阵没有的条款号 | 引用指向已删或写错的条款 | 删掉那处引用，或补回条款 | `orphan_clause` |
| 已取证条款数低于基线 | 棘轮只许增，调低就是悄悄丢掉已验收的能力 | 补回证据，或证明是误判后显式改 `M.INFER_EXCEPTIONS` | `ratchet_evidenced` |
| 索引生成块与分片不一致 | 手改计数，或改了条款没跑 `--write` | 跑 `lua tools/cli.lua acceptance --write` | `index_stale` |

**禁用措辞表**（唯一来源是 `tools/acceptance.lua` 的 `M.VAGUE_WORDS`，两处必须一致）：`正确`、`合理`、`符合预期`、`手感要好`、`可行`、`正常`。

只认**独立成句**的用法：词后紧跟句读（`，。；、：！？（）「」`）或到单元格结尾才算命中。`正常流程`、`正常金币`、`连通可行走` 这类构词不算，否则会把已经说清楚的条款一起判红；所以「结果正常。」会被拦，而「鱼顶在头上时模型贴在头顶、不穿进角色身体」不会被拦。判断办法很简单：**删掉那个词之后，这句话还能不能判真假？**能判的留着，不能判的改写。

### 6.2 评审判红（门禁不查）

| 现象 | 为什么不算 | 怎么改 | 机器为什么判不了 |
| --- | --- | --- | --- |
| 一条里塞「A 且 B」两件独立的事 | 部分成立时无法记状态 | 拆成两条 | 中文没有句子边界，「且」可能只是同一件事的两个侧面；正则一拆就把说清了的条款拆碎 |
| 把实现内部模块名写进 A 级条款 | 把实现细节锁死，重构就变红 | 改成玩家可观察的结果，或降为 B 级 | 门禁只看文本，分不出这是模块名还是玩家能看见的名词；口径在 [证据分级](evidence-levels.md) 第一节 |

差与好的对照：「钓鱼手感要好」不可判；「抛竿后到鱼上钩之间，玩家可以按取消键中止本次抛竿，鱼饵不消耗」可判。

## 七、提交前自查

新增或修改条款后，在仓库根目录跑：

```bash
# 各分片解析出的条款行数
grep -c '^| [0-9]\+-[0-9][0-9] |' docs/acceptance/[0-9][0-9]-*.md

# 条款行是否都带等级后缀（没有输出即通过）
grep -n '^| [0-9]\+-[0-9][0-9] |' docs/acceptance/[0-9][0-9]-*.md | grep -v '（[ABC]） |$'

# 编号连续性：人工核对输出里有没有缺号或重号
grep -o '^| [0-9]\+-[0-9][0-9] |' docs/acceptance/[0-9][0-9]-*.md | sort
```

门禁一次核这些事：19 个规格小节各恰好一份分片、条款 ID 从 01 起连续不跳号、等级后缀合法、文案里没有禁用措辞、索引生成块与分片一字不差、证据文件不引用矩阵里没有的条款号、已取证条款数不低于基线。命令是 `lua tools/cli.lua acceptance --check`，它随 fast 车道跑；`acceptance --infer` 单独列出反推出的状态与证据路径。
