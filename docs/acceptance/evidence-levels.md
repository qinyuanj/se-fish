# 证据分级：什么算取证，什么不算

> 本文件规定分片里「证据等级」后缀的判定口径：哪些条款**必须** A 级、哪些**只能** C 级、以及什么样的结果不足以记为取证。
> 写法见 [TEMPLATE.md](TEMPLATE.md) 第三节，可照抄的样本见 [09-multiplayer-rules.md](09-multiplayer-rules.md)。
> **Evidence / 取证**：_Avoid_: 验证过、测过、自测、verified
> **Evidence level / 证据分级**：_Avoid_: 优先级、等级、severity、级别

## 一、三档证据

这里分的是**怎么取证**，不是**取证什么**：每个业务系统要覆盖的那四栏（正常流程、失败流程、退出重进、存档恢复）见 [ADR-0028](../adr/0028-solo-clear-on-shared-world.md)；一栏里的每一条条款再按下面三档取证。

| 等级 | 取证方式 | 判的是 | 落点 |
| --- | --- | --- | --- |
| **A** | 走业务入口的黑盒断言：只经 `server/main.lua` 组合的宿主服务或 `ServerRuntime` 公开入口进入，只断言玩家可观察的结果 | 程序算出来的结果：数值、边界、路由、结算后置状态 | `tests/native/spec/`（spec 车道，随 full 跑） |
| **B** | 时序探针：可重跑，但要编排时钟、重连、迟到回调、超时与并发争抢 | 状态机在时间轴上的行为：幂等、fencing、恢复 | 现有 `tests/native/` 用例或专项探针 |
| **C** | 试玩观察：在编辑器试玩里看、走、点 | 只有人在地图里才能判的性质：贴地、净空、遮挡、可读性、手感 | 试玩会话记录，写进 `evidence/*/session.md` |

**A 级的入口只有一个方向**：从客户端请求进、从玩家能看见的地方出。断言可以落在回复载荷、服务端推送、世界里的对象、存档快照上；不能落在「某个内部函数被调了几次」或「某个字段正好等于某个实现私有值」上——那样钉住的是实现，不是条款。

**A 级不认「旧测试通过」**：`tests/native/` 里的既有用例多数是实现自检（断言内部函数、夹具细节），它们通过只说明实现没坏，不说明条款成立。条款要转成 `evidenced`，必须有一条专门对应它的、走业务入口的断言，且断言正文里出现条款号。

## 二、必须 A 级

下面这些条款判的是「程序算出来的结果」，用探针或试玩都不足以判真假，**只能** A 级：

- **数值与边界**：血量上限、移速百分比、烤制倍率曲线、返程票价公式、弹容量取整、封顶与超限拒绝。
- **表格与库存**：鱼种表、物品表、商店行、抽奖图案、盲盒条目、航线的条数与身份；升级是逐级购买还是可跳级。
- **结算的原子性**：一次请求里扣费与发奖是否同时落地、失败时是否两边都不动、重复提交是否只结算一次。
- **路由与优先级**：兑换优先于回收、特殊招式目标优先于自动选目标、手持切换的两次点击语义。
- **存档形状与升级**：字段是否入库、v1 旧档升级后的默认值、重连后哪些状态恢复、哪些不续播。

判断口诀：**把玩家换成一台只看回包的机器，这条还判得动吗？**判得动就必须 A。

## 三、只能 C 级

下面这些条款判的是「人在地图里能不能用」，任何自动化都替代不了，**只能** C 级：

- 视觉可读性与遮挡：界面对手机分辨率可读、奖励与按钮不被遮挡、烤制倍率读数在外面看得清。
- 物理与空间：玩家贴地、船体不挡上下船、放大到 3 倍后不穿墙不抖动、鱼饵刷新点与提示可区分。
- 手感与操作距离：5 米交互在场景里够用、2 米邀请不会误选路人、长按落点指示与实际落点一致。
- 整体旅程：以正常收入一次走完七区、退出重进后进度连续。

C 级条款的状态由反推给出：没有试玩会话标 `✅` 就是 `blocked`，不需要手写理由；有了 `✅` 就是 `evidenced`。规格内没有永久出界（[ADR-0029](../adr/0029-scope-completeness-and-placeholder-first.md) 第一节）。

取证后在 `evidence/<日期>-<会话号>/session.md` 的对照表里把该条标 `✅`，记录含抓屏清单与观察结论。`⏸`（未覆盖）、`⚠️`（部分观察）、`⛔`（观察到不符）都不算取证。

- **Playtest acceptance / 试玩验收**：合法输入为条款 ID、可重跑操作步骤与观察目标；从**新档**开始，按 [开发工作流](../agents/workflow.md#试玩存档隔离) 使用 QA 存档槽。**留证**是仓库内的会话记录、抓屏清单与观察结论。
  _Avoid_: 实机测试、真机验收（指编辑器试玩时）、QA test
- **Physical device / 真实设备**：玩家实际使用的手机或客户端平台；其验收结果与编辑器试玩分场、分记录，不互相替代，不新增或改变 A/B/C 三档证据语义。
  _Avoid_: 实机（未说明环境时）、real device

## 四、什么不算取证

- 编辑器内模拟平台回调成功，被记成平台条款已取证（按占位口径记 `unverified`，真实渠道结论进生产开关台账）。
- 单人开两个客户端模拟多人容量，被记成多人条款已取证。
- 实现写完了、代码看过了、PR 合了——这些是「做完了」，不是「验证过了」。
- 旧测试通过：与条款没有一一对应的断言，不能当证据。
- 证据文件只在注释里提到条款号，没有断言这条规矩——那是引用，不是证据；用 `M.INFER_EXCEPTIONS` 显式登记例外，不改文案绕过。

## 五、门禁怎么核

`lua tools/cli.lua acceptance --check`（随 fast 车道跑，见 `tests/native/guards/acceptance_matrix_test.lua`）会实际去核：

- 每条条款的等级后缀必须是 A、B 或 C（`clause_level`）。
- 证据文件里出现的条款号必须都在矩阵里（`orphan_clause`）：引用了已删条款就红。
- 已取证条款数只许增（对照 `docs/acceptance/baseline.lua`）。
- 条款文案不许出现禁用措辞（清单与判定办法见 [TEMPLATE.md](TEMPLATE.md) 6.1）。

状态本身由 `tools/acceptance.lua` 的 `M.infer` 反推，`lua tools/cli.lua acceptance --infer` 可以看到每条推出来的状态与证据路径。

证据等级本身写错（例如把一条只能 C 级的条款标成 A、并配一条根本不判那件事的断言）**机器拦不住，靠评审**：判据是这条断言失败时，条款是否真的不成立。
