# 《渔力全开》策划案内部矛盾与待决题

来源：`design`（策划案正文、钓鱼表、物品表、抽奖表）与 `docs/GameSpec.md` 的逐节对照核对。
去向：每题确认后从本清单删掉，移进[策划案已确认结论](策划案已确认结论.md)；本文件只留还没定的题。题号随删题重排，跨文件引用一律用问题标题，不引用题号。

**数值缺口的口径**：缺的是**数值**时，先在共享配置（`common/GameCfg.lua` 与 `common/cfg/` 的内容表）里放占位值并就地标「未查证」，同时在这里记一笔并写明影响哪条条款；不靠记忆、不写在工单或聊天里。真实数值到位后只替换配置，不改玩法判定（见 [ADR-0029](adr/0029-scope-completeness-and-placeholder-first.md) 第三节）。

## 逐题

### 他人抢救的耗时与打断规则

问：他人抢救濒死玩家要按几秒结算？抢救过程中施救者被攻击是否打断、被打断后进度是否清零？

现状：规格只写「2 米内可抢救」「成功后恢复血量上限 10%」，耗时与打断都没有；共享配置里对应字段暂时标「未查证」。

待定：由策划补一条数值与打断规则；在补上之前，代码只按「一次请求结算一次、恢复 10%」实现，不自行发明耗时。

### 队伍界面的布局

问：队友头像与血量显示在屏幕哪一侧、最多显示几名队友、与自身血量条的距离是多少？

现状：规格只要求「在 HUD 上显示本队队友及每名队友的当前血量」并且「实机分辨率下可读、不与左上角自身血量重叠」，没给布局参数。

待定：由策划给一版布局草图；在补上之前按「右侧竖排、最多 2 名队友（小队上限 3 人）」实现，并在试玩取证时连同 9-23 一并复核。

### 金币页的占位汇率

问：真实商品 ID 与金币兑换汇率交付前，金币页用哪个占位汇率演示购买与到账？

现状：真实汇率属于平台侧交付，仓库内不自定取值（原 7-25 的旧口径）；按 ADR-0029 的占位优先口径需要一个明确的占位值。

待定：由策划与商业化确认一个只用于演示的占位汇率；真实汇率到位后只替换配置，不改判定。
