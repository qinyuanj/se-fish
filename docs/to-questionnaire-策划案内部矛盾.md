# 《渔力全开》策划案内部矛盾与待决题

来源：`design`（策划案正文、钓鱼表、物品表、抽奖表）与 `docs/GameSpec.md` 的逐节对照核对。
去向：每题确认后从本清单删掉，移进[策划案已确认结论](策划案已确认结论.md)；本文件只留还没定的题。题号随删题重排，跨文件引用一律用问题标题，不引用题号。

**数值缺口的口径**：缺的是**数值**时，先在共享配置（`common/GameCfg.lua` 与 `common/cfg/` 的内容表）里放占位值并就地标「未查证」，同时在这里记一笔并写明影响哪条条款；不靠记忆、不写在工单或聊天里。真实数值到位后只替换配置，不改玩法判定（见 [ADR-0029](adr/0029-scope-completeness-and-placeholder-first.md) 第三节）。

### 近战与范围组起手与走廊宽度

问：电鳗放电、帝王蟹乱刺、蟹老板双击与冲撞的起手各几秒？鳄雀鳝的「间隔 1.5 秒」是否可直接当作起手窗？冲撞线形预警走廊取多宽？

现状：正文只给节拍与伤害。逐招表 [未查证] 占位：电鳗放电 0.5 秒；帝王蟹乱刺起手 0.5 秒（六刺仍按 0.2 秒间隔）；蟹老板双击 0.5 秒、冲撞 0.5 秒且走廊宽 2.5 米；鳄雀鳝以 1.5 秒攻击间隔兼作起手窗（表未单列起手）。虾霸的起手取 2 秒攻击节拍，蟹老板旋转取首段碰触前的 1 秒。以上都落在 `common/cfg/BossMoves.lua` 的 Warning.WindupSec / Width，真实数值到位只替换该表；12-49～12-51 的试玩可读性仍待整批取证。
## 逐题

### 他人抢救的耗时与打断规则

问：他人抢救濒死玩家要按几秒结算？抢救过程中施救者被攻击是否打断、被打断后进度是否清零？

现状：规格只写「2 米内可抢救」「成功后恢复血量上限 10%」，耗时与打断都没有。`common/GameCfg.lua` 的 `GameCfg.Rescue` 里 `DurationSec = 2`（耗时）、`InterruptMoveMeters = 1`（施救者移动打断阈值）、`InterruptOnDamage = true`（施救者受击打断）三项均就地标 `[未查证]`；2 米范围与 10% 恢复是规格原文，不在此列。

待定：由策划补一条数值与打断规则；补上后只替换上述三个配置字段，不改 `server/Mgr/MgrSurvival.lua` 的相位推进与 `server/Mgr/MgrInteract.lua` 的交互复验，也不改 `tests/native/spec/09_rescue_test.lua` 的幂等断言。占位期间代码仅保证「两米内发起、耗时到点结算、打断回濒死、重复只算一次」这条路径完整，不宣称数值已获策划确认。

### 队伍界面的布局

问：队友头像与血量显示在屏幕哪一侧、最多显示几名队友、与自身血量条的距离是多少？

现状：规格只要求「在 HUD 上显示本队队友及每名队友的当前血量」并且「实机分辨率下可读、不与左上角自身血量重叠」，没给布局参数。

待定：由策划给一版布局草图；在补上之前按「右侧竖排、最多 2 名队友（小队上限 3 人）」实现，并在试玩取证时连同 9-23 一并复核。

### 邀请已在队伍中的玩家

问：A 队里的甲邀请已在 B 队的乙，应该拒绝这次邀请，还是让乙接受后自动从 B 队换到 A 队？

现状：规格只写「一支小队最多 3 名玩家」「只有在 2 米内才能邀请」，没有换队语义；换队还牵出「B 队少一人是否解散」的连带判定。

待定：由策划确认换队是否合法。在此之前实现按「拒绝邀请」处理（原因码 `target-in-party`），玩家要换队须先主动离队，
不替玩家隐式解散或离开原队伍。

### 金币页的占位汇率

问：真实商品 ID 与金币兑换汇率交付前，金币页用哪个占位汇率演示购买与到账？

现状：真实汇率与真实商品 ID 属于平台侧交付（原 7-25 的旧口径是「仓库内不自定取值」）。按 ADR-0029 的
占位优先口径，现在在共享配置 `GameCfg.Platform.Placeholder.CoinPage` 里放了明确标「未查证」的占位值：
`CoinPerUnit = 100`（1 元 → 100 金币），两份演示商品 6 元 → 600 金币、30 元 → 3000 金币，商品 ID 用
`placeholder.goods.coin.*` 前缀与真实 ID 区分。占位通道只在地图内到账金币，不发放真实付费权益（#261）。

待定：由策划与商业化确认正式汇率与商品 ID；到位后只替换 `GameCfg.Platform.Placeholder` 这张表并置
`Enabled = false`，玩法判定与结算顺序不动。

### 各招式的起手时长与单人躲避窗口

问：每招的预警起手与躲避窗口各给几秒？哪些招式不需要起手？

现状：规格第 12 节只要求「必须可观察预警」「每个招式都留出可完成的单人躲避窗口」，秒数全部缺失。逐招表 `common/cfg/BossMoves.lua` 按「预警期内离开形状」给了占位值：跺脚 0.8 秒、吐息 1.5 秒、大部分精英招 0.5～1 秒，全部标 `Warning.Unverified = true`；爪击、甩尾这类贴身招不起手，只列「保持在范围外」的躲避窗口。

待定：由策划给一版逐招起手时长；补上之前不改判定，只替换表里带 [未查证] 的字段。

### 哥斯拉跺脚的周期与范围

问：跺脚多少秒一次、作用范围多大、伤害多少？

现状：GameSpec §12 只写「保留正文跺脚及对应范围」，正文不在本仓库（`design` 未挂载），逐招表暂按 2 秒 / 脚边 10 米 / 150 伤害 [未查证]（12-41）。

待定：策划补正文数值；在补上之前，断言只保证「跺脚是独立一招、有圆形预警、伤害与范围与表一致」。

### 虎鲸虎啸与风神翼龙的独立伤害

问：虎啸、投掷、俯冲各自的伤害是多少？

现状：钓鱼表只给通用攻击 35，正文给投掷 100 / 俯冲 260（12-34 要求核对映射、不得静默丢弃），虎啸完全没有数值；逐招表按正文与已有披露值填写并标 [未查证]（12-28、12-34）。

待定：由策划确认三段的伤害；核对前不改配置。
### 平台成就的占位 ID

问：真实成就 ID 交付前，调试构建里用哪个占位成就 ID 走通「查询 → 提交」补交路径？

现状：共享配置 `GameCfg.Achievements.final.PlaceholderId` 暂取 390001（标「未查证」）；占位 ID 永不落「已送达」，
平台对它的回答不代表本成就已授予。生产构建（`GameCfg.Debug.Enabled` 关）不拿占位 ID 去问或去写平台。

待定：由平台侧确认占位值（须确认不与正式成就 ID 冲突）；真实 ID 到位后只替换 `PlatformId`，判定不动。

### 上限之后药水的赠送方式

问：药水到上限后，多出来的那几瓶要怎么送给其他玩家——是丢在地上让对方捡，还是走一个单独的赠送请求？如果是请求，是否要求双方在线、有没有距离限制、能不能跨区？

现状：规格第 2 节写「到上限后的药水可赠送给其他玩家」，但仓库里没有任何玩家之间的赠送或转移通道：`MgrLoot` 只处理拾取（`Give` / `GiveBait`），`server/`、`common/` 下也搜不到赠送相关的远程事件。眼下唯一能让物品换手的路径是「丢到地上 → 别人捡起」，而丢弃协议本身也只覆盖鱼获与信物，不覆盖药水。

影响：条款 2-11 保持 `unverified`；实现侧按「暂不开放药水丢弃/赠送」处理，不凭猜测造协议。覆盖表里 2-11 的代码落点只登记到 `MgrPlayerData` / `MgrLoot` 的既有拾取路径，并注明跨玩家转移缺失。

待定：由策划确认赠送走哪条路（丢地拾取还是单独请求，含在线/距离/跨区限制）；定案后补协议、补 `tests/native/spec/` 断言，再把 2-11 转 `evidenced`。

现状：钓鱼表只给沧龙基础攻击 35，§12 正文只描述动作而没有独立伤害（12-36）。逐招表按基础攻击填砸击 35、甩头 35 并标 [未查证]；服务端权威配置 GameCfg.Ability.Aquatic 直接取逐招表那两行，试玩数值到位只改配置。

### 远程与俯冲段的落点、轨迹与危险区形状

### 官方 AI 搜敌优先级类型

问：官方 AI 管理器的搜敌优先级类型（priorityMode）有哪些取值，哪一个代表「按伤害优先」？

现状：上游 official_ai_feature 只预留了字段并在包内存档，接口注释写明「当前搜敌按距离最近」，没有给出枚举。因此 common/GameCfg.lua 的 Ability.AiTarget.PriorityMode = 1 是 [未查证] 占位值；伤害优先的裁决由业务侧适配层完成，官方管理器只持有裁决结果，真实枚举到位后只替换配置。

待定：由官方包维护方给出枚举；影响 6-29。
